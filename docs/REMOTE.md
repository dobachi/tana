# リモート接続（SSH / SFTP, FR-20）

ssh で入れるマシンのファイルを、手元のファイルと同じようにペインで開く。
相手側には **何もインストールしなくてよい**（sshd の SFTP サブシステムがあれば動く。普通の Linux / macOS / Windows OpenSSH サーバなら有効）。

## 開き方

- **`Ctrl+Shift+X`**（Fude と同じ）か **`o → s`**、またはメニュー「ファイル」→「リモート接続…」で接続画面を開き、接続先とパスを入れて「開く」（閉じるのは右上の × か Esc）
  - 接続先: 最近使ったもの・接続中のもの・`~/.ssh/config` の Host 名が候補に出る。`user@host` も可
  - パス: 空欄＝相手のホーム、`~/x`・`x` はホーム基準、`/etc` のような絶対パスはそのまま
- **`Ctrl+L`** で `sftp://k16/home/you` のように直接打ってもよい（`sftp://k16` だけならホーム）
- リモートにいる間、`Ctrl+L` に相対パス（`logs`、`../etc`）を打つとその場所基準で移動する
- お気に入り・タブ・ワークスペース・セッション復元にもそのまま入る
  （起動時に復元するリモートは、繋がるまでいったん手元のホームを出し、繋がったら移る）

リモートを表示しているペインは、見出しに 🌐 と `k16:` が付き、タブ名も `k16:notes` のようになる。

前提: **パスワード入力なしで `ssh 接続先` できること**（鍵認証・ssh-agent・Tailscale SSH など）。
画面からパスワードは聞けない。初めての相手（この PC の ssh にホスト鍵が未登録）なら、
Tana が「鍵を登録して接続しますか？」と確認し、承認すると登録して繋ぐ（`StrictHostKeyChecking=accept-new` 相当。
**鍵が変わった相手は確認も出さずに拒否**する）。Windows 版と WSL 版は ssh の `known_hosts` が別なので、それぞれで一度確認が出る。

## 閲覧のみ（既定）と書き込み

接続は**既定で閲覧のみ**。一覧・移動・プレビュー・開く・リモート→手元へのコピーはできるが、
相手側を変える操作（コピー/移動の宛先にする、改名、新規フォルダ、削除、リモートからの移動）は断られる。

書き込むには二つのゲートを両方開ける:

1. 接続画面の「書き込みを許可する」（開くときにチェック、または「接続中」一覧の接続ごとのチェック）
2. いつもの操作モード（`Ctrl+Shift+Space`）

書き込みの許可は保存しない。アプリを起動し直すと、どの接続も閲覧のみに戻る。

| 操作 | 閲覧のみ | 書き込み許可 |
| --- | :---: | :---: |
| 一覧・移動・プレビュー（テキスト/Markdown/画像） | ✅ | ✅ |
| 開く（既定アプリ / 外部アプリ / WSL の Windows 側） | ✅（一時コピー） | ✅（一時コピー） |
| リモート → 手元へコピー（F5 / Ctrl+C→V / D&D） | ✅ | ✅ |
| 手元 → リモート、リモート同士のコピー | — | ✅ |
| 移動・改名・新規フォルダ・削除 | — | ✅ |

## 知っておくこと

- **開く**は相手のファイルを手元の一時フォルダ（`<temp>/tana-remote/<接続先>/…`）へ取得して、その写しを開く。
  **写しを編集・保存しても相手には戻らない**。相手を編集するなら Fude のリモート接続を使う
- **削除**: リモートにゴミ箱は無い。`Delete` でも完全削除の確認が出る
- **検索**（`Ctrl+F` / `/`）とファイルマネージャでの表示（`o → r`）はリモートでは使えない
- 自動更新はリモートでは 6 秒おき（手元は 1.5 秒）
- リモート同士のコピー（別の接続先どうしも可）は手元の一時フォルダを経由する
- 回線が切れたら、次の読み取りで一度だけ自動で張り直す。ssh は 15 秒ごとに相手の生存を確かめる
- 「切断」すると、その接続先を表示しているペインは手元のホームへ戻る

## 仕組み

Tana が `ssh -o BatchMode=yes -o ClearAllForwardings=yes -o ControlMaster=no … -s -- 接続先 sftp` を起動し
（`~/.ssh/config` にある Fude 用の `RemoteForward` や接続共有を横取りしない）、その標準入出力で SFTP v3 を話す
（`src-tauri/src/sftp.rs` は依存を増やさない最小実装、接続管理は `remote.rs`）。
アプリ内ではリモートの場所を `sftp://接続先/絶対パス` という文字列で表し、`backend.js` がリモートなら
`remote_*` コマンドへ振り分ける。ペイン・タブ・お気に入り等はローカルと区別しない。

## 困ったとき

| 症状 | 見るところ |
| --- | --- |
| `… に接続できません（Permission denied (publickey).）` | 鍵認証が通っていない。端末で `ssh 接続先` がパスワード無しで通るか |
| 「初めての接続先です」の確認が出る | その PC の ssh が相手の鍵を知らない。承認すれば登録される（端末で一度 `ssh 接続先` → `yes` でも同じ） |
| `… に接続できません（Host key verification failed.）` | 鍵が**変わった**相手（再インストール・なりすまし等）。理由を確かめてから `ssh-keygen -R 接続先` で古い鍵を消す |
| `… に接続できません（Could not resolve hostname …）` | `~/.ssh/config` の `HostName` |
| `… は閲覧のみの接続です` | `Ctrl+Shift+X`（`o → s`）の接続画面で「書き込みを許可」 |
| `ssh を起動できません` | `ssh` コマンドが PATH に無い（Windows は「OpenSSH クライアント」機能を有効に） |
